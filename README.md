# Hospital Staff Portal

Hospital Staff Portal is an ASP.NET Core MVC application for managing hospital
staff workflows and patient-related records. It demonstrates a layered .NET
architecture, ASP.NET Core Identity authentication, Entity Framework Core
data access, Razor views, and automated tests.

> **Portfolio/demo project:** the application uses generated sample data and is
> not intended for real patient information or clinical use.

## Features

- Manage doctors, patients, appointments, diagnoses, and medical records.
- Register and authenticate users with ASP.NET Core Identity.
- Optional Google OAuth and SendGrid email integration.
- Optional OpenAI-powered sample data generation during development seeding.
- SQL Server migrations for application data and an in-memory database test host.
- Reusable domain, data, facade, infrastructure, and MVC web layers.

## Technology

- .NET 9 and ASP.NET Core MVC
- Entity Framework Core 9 and SQL Server
- ASP.NET Core Identity
- MSTest and `WebApplicationFactory`
- Bootstrap, jQuery, and Select2

## Solution structure

| Project | Responsibility |
| --- | --- |
| `Soft` | ASP.NET Core MVC web application, Identity, migrations, and services |
| `Domain` | Domain entities and repository contracts |
| `Data` | Persistence-facing data models and enums |
| `Infra` | Entity Framework repository implementations |
| `Facade` | View models and presentation-facing factories |
| `Core` | Shared abstractions and HTML helpers |
| `Aids` | Validation, utility, and design-pattern helpers |
| `Tests` | Unit and MVC integration tests |

## Prerequisites

- .NET 9 SDK
- SQL Server LocalDB for the default development connection string
- Optional: OpenAI, Google OAuth, and SendGrid credentials for integrations

## Run locally

1. Clone the repository and enter its directory.
2. Restore and build the solution:

   ```powershell
   dotnet restore MVC.sln
   dotnet build MVC.sln --configuration Release
   ```

3. Run the web application:

   ```powershell
   dotnet run --project Soft\Soft.csproj
   ```

4. Open the URL printed by ASP.NET Core. In Development mode, the application
   applies migrations and attempts to seed sample data.

The checked-in configuration contains no credentials. Configure optional
services with .NET User Secrets from the `Soft` project:

```powershell
dotnet user-secrets set "OpenAI:ApiKey" "<your-key>" --project Soft\Soft.csproj
dotnet user-secrets set "AuthMessageSenderOptions:SendGridKey" "<your-key>" --project Soft\Soft.csproj
dotnet user-secrets set "Authentication:Google:ClientId" "<your-client-id>" --project Soft\Soft.csproj
dotnet user-secrets set "Authentication:Google:ClientSecret" "<your-client-secret>" --project Soft\Soft.csproj
```

Google authentication is registered only when both Google values are present.
OpenAI-backed seeding and email delivery require their respective credentials.

## Test

Run the automated test suite with:

```powershell
dotnet test MVC.sln --configuration Release
```

Tests use an in-memory database where appropriate. Tests that call external
services require the corresponding credentials and should be treated as
integration tests.

## Security and privacy

Never commit API keys, OAuth secrets, database passwords, real patient data, or
publish profiles. Use User Secrets or environment variables for local and
deployed configuration. The sample records generated by this project are
fictional.
